File Organization

i When a release carries a MusicBrainz disambiguation (edition note) and your template doesn't place $disambiguation itself, it is added to the album folder automatically. When a recording carries its own disambiguation (version note, like “acoustic”) and your template doesn't place $track_disambiguation itself, it is added to the track filename automatically. This keeps same-named releases and same-titled recordings apart — turn it off and your template is respected exactly as written.
Your templates, filled in with an example release:
i Variables: $albumartist, $artist, $artistletter, $albumartistletter, $album, $albumtype, $title, $track, $disc (01), $discnum (1), $cdnum (CD01): these three only appear on a multi-disc album, so a single-disc album isn't stamped 01- on every file. $discalways (01) and $discnumalways (1) appear on every album, $year, $quality (filename only), $disambiguation (the release's edition note, like “baby punk version”; added to the album folder automatically when your template leaves it out, unless “Automatically add disambiguation” above is turned off), $track_disambiguation (the recording's version note, like “acoustic”; added to the filename automatically when your template leaves it out, unless the same toggle above is turned off), $explicit ([E] on explicit tracks, nothing otherwise), $contentrating ([E] or [C]) and $contentratingfull ([Explicit] or [Clean]); these stay empty when the source doesn't say, and in a folder they follow the album, not the track. To tell same-named artists apart: $albumartistdisambiguation (MusicBrainz's note, like “US grunge band”), $albumartistcountry (US, GB, JM), $albumartistgenre, $albumartistinfo (the first of those three the artist has), $albumartistcomposite (the note, else country and genre together, like “US Rock”) and $albumartistclash (the same as info, but only when another artist in your library shares the name, so $albumartist ($albumartistclash) keeps unique artists plain). The $artist versions ($artistinfo and so on) describe the track artist. They come from enrichment, so an artist that hasn't been matched to MusicBrainz yet renders nothing. The three disc variables work in a folder segment as well as in the filename and are empty on a single-disc album, so $albumartist/$album/Disc $discnum/$track - $title gives you a disc folder only where there is more than one disc. Put any of them in the template and it replaces the automatic disc folder from “Multi-Disc Folder Label” below. Use ${var} to append text: ${albumtype}s → Albums
i A soundtrack or compilation is filed as a compilation instead of whichever contributor happened to be downloading — without this, one guitarist featured on 45 soundtracks collects all 45 albums. Compilations are filed with the Compilation Path Template below, not the album one. Each track still credits the artist who actually recorded it. A release counts as a compilation when it is credited to Various Artists, when the metadata source types it one, or — when reorganizing, where the whole tracklist is known — when three or more tracks have different artists and none of them owns more than half the album. A soundtrack credited to a single composer is left with that composer. Also governs whether reorganize gives compilations their own folder layout.
i Used instead of the album template for soundtracks and compilations (see “Detect multi-artist compilations” above). Same variables as the album template; $albumartist is the release's credit (often Various Artists) and $artist is whoever recorded the track. To file compilations exactly like albums, give it the same template as the album one.
i Variables: $albumartist, $artist, $artistletter, $albumartistletter, $title, $track (01), $album, $albumtype, $year, $quality (filename only). Use ${var} to append text: ${albumtype}s → Singles

Empty = keep the original library filename.
i Variables: $artist, $artistletter, $title, $year. Use ${var} to append text. Default: $artist/$title-video
i Variables: $artist, $track, $album, $chop (the save name), $stem (drums/vocals/bass/other, empty for the full mix). Default: $artist/$track - $chop. Empty segments collapse — a chop with no album info won't leave a stray folder. Use ${var} to append text.
i Label for the disc subfolder SoulSync adds automatically on a multi-disc album (Disc 1/). Ignored when your path template already places the disc itself with $disc, $discnum or $cdnum — the template wins.
i How $albumartist resolves when a release has multiple artists — this governs the FOLDER your music sorts into for both albums and singles (the default templates use $albumartist). "First Listed" uses only the primary artist for folder names (e.g., "Larry June" instead of "Larry June, Curren$y & The Alchemist"). Full artist list is always preserved in file metadata tags.
i When $artistletter is used in templates: artists starting with digits, symbols or non-Latin scripts all sort into a single # folder instead of one folder per character ("365 Days" → #/, "北京" → #/). Accented letters fold to their base letter (Édith Piaf → E/). Off = the literal first character, exactly as before.
i Windows doesn't allow : ? / \ " * | < > in file or folder names. Off, they become _ (AC_DC). On, they become lookalike characters that work everywhere (AC∕DC, What's Going On？), and a trailing dot is kept (DAMN․). Applies to new downloads; run Reorganize to rename what's already there.
i Separator between multiple artists in the ARTIST tag (e.g. & matches MusicBrainz/Picard style)
i Write each artist, and each genre, as a separate tag value (one GENRE= per genre) for Navidrome/Jellyfin/Plex. Off writes one comma-joined value
i Keep only primary artist in ARTIST tag, append others as (feat. ...) in title
i When enabled, the same song can be added to the wishlist from different albums (e.g., completing a discography where albums share tracks). When disabled, tracks with the same name and artist are skipped.
i Wing It means a track couldn't be matched in the metadata catalogue — these are unmatched guesses, not tracks missing from your library. Off by default: guesses stay in the Wing It Pool for manual review. Turn this on to let guesses be searched like any other wishlist track.
i When you remove or cancel a wishlist track, SoulSync remembers not to re-add it automatically for this many days. Lower it (e.g. 7) to give removed tracks another chance sooner.

Library Organize

When the Library Organize tool re-matches a track, the metadata source often differs from files you've already organized: capitalization, release year (a reissue [2023] "corrected" to the source's 2020), or disc layout (a single-disc album matched to a deluxe 2-disc edition, stamping a bogus "0211" prefix). With this on (default), a title/album differing only by letter-case, your own album year, and a genuinely single-disc album's numbering are all left alone — no needless renames. Turn off to match the metadata source exactly.
When an import creates an artist folder, also write a Kodi-format artist.nfo containing the artist's name and MusicBrainz artist ID, so Jellyfin / Kodi / Emby identify the artist instead of guessing by name. A folder with no artist artwork also gets poster.jpg and background.jpg (fanart.tv, TheAudioDB or Deezer), which Plex reads as local art. Nothing already in the folder is replaced, an artist.nfo with a different ID included. To backfill folders you already have, run the Artist NFO Backfill repair job.
Audiobook organizationNaming, quality, tags & recycle
i Variables: $author, $authorletter, $narrator, $title, $series, $seriespos (01), $year, $asin. Default: $author/$series/$seriespos - $title. Books with no series collapse the series folder and its number cleanly, the same way podcast season folders do. Use ${var} to append text.
i Deleting a book MOVES it to a hidden .deleted folder inside your audiobook library instead of erasing it, so a mis-click can be undone. The folder is hidden so Audiobookshelf, Plex and Jellyfin do not keep showing books you removed. Note the space is not freed until the bin is emptied. Off, deletes are permanent immediately.
days i How long a deleted book stays recoverable before the daily cleanup erases it for good. 0 turns the bin off — it does not mean "erase everything now", because purging on that reading would destroy what was recycled while the bin was still on. Default: 7

Downloads & Import

Books use the same torrent, usenet and Soulseek clients as music — set those up under Sources.
i Which Audible storefront the audiobook catalogue pages, author scans and follow checks query. Some titles are exclusive to one country's store, so picking the store you buy from finds books the US store never lists. Default: us
i Which sources a book search asks. Separate from the music chain on purpose — Tidal, Qobuz, HiFi and Deezer carry no audiobooks at all, so a book on the music chain would burn an attempt on each of them before it could succeed. The clients themselves are the same ones music uses; only the order and the category differ.
i The category SoulSync tags audiobook torrents and NZBs with in your download client. Keep it different from your music category so a finished book is never picked up by anything watching for music. Default: audiobooks
i Newznab category IDs searched for audiobooks. 3030 is the standard audiobook category and is deliberately kept OUT of music searches, so asking for it here costs the music side nothing. Only change this if your indexer uses a non-standard ID.
% i How much of the runtime Audible publishes has to actually be on disk before a book is filed into your library. A download client reports "complete" when the files it was asked for finished, which is not the same as the book being whole — and a book missing its last chapters plays perfectly until you run out of it. Short books are held in staging, never failed outright. Default: 92
days i How long an incomplete book is kept staged before it is failed and sent back to the wishlist. Torrents finish late and uploaders repair releases, so patience is right here; forever would mean one broken release holds a wishlist row for good. Default: 7
i Chapter files arrive named however the uploader left them. On by default: a book whose files sort wrong plays wrong. Turn this off only if you trust your releases' own numbering.
i Off by default: when a book arrives as many files, combine them into a single .m4b with one chapter marker per file during import. Needs ffmpeg on the server (the Docker image ships it). The originals are only removed after the merged file verifies, so a failed merge never loses the book.
i Off by default: a book that is downloaded or found in your library stays on the wishlist, marked "In library". Turn this on to drop it instead, the way the music wishlist does.
i Embeds title, author, series and narrator into each file on import. Narrator goes in the COMPOSER field, which is the convention every audiobook server settled on. Without this a book keeps whatever the uploader's ripper wrote, which is usually chapter 4 of a 27-hour book tagged as a track on an album called "audiobook".
i Embeds the cover into every chapter file. A cover the release already shipped is preferred over fetching one, so this still works offline.
i Writes cover.jpg into the book folder. Plex, Jellyfin, Audiobookshelf and Booksonic all read it from there.
i Writes metadata.opf (Audiobookshelf, Plex, Calibre) and book.nfo (Kodi, Jellyfin, Emby). Both, because the servers genuinely disagree about which to look for and they are a few hundred bytes each. These also carry the ASIN, which is what lets the daily library scan recognise a book you imported months ago.

Subtitles
Fetch external .srt files next to the video from the provider chain below, only for what's missing. On by default for new imports — free tiers are quota-limited (~20 downloads/day each), so anything missed is retried later.
Language codes to fetch, in priority order (e.g. en,es). One .srt per language is written as <video>.<lang>.srt. Each code is 2–3 letters; separate codes with commas, spaces, or semicolons.
A tiebreak only, never a filter: when two subtitles score the same, the hearing-impaired one (sound cues, speaker names) wins.
On top of the full track, fetch a forced (foreign-parts-only) track per language, written as <video>.<lang>.forced.srt — the lines for scenes in another language, for when you watch without full subtitles. Many titles have none, so these often stay missing.
Before fetching, SoulSync checks what the video already has: any sidecar next to it (.en.srt, .eng.srt, .English.sdh.srt, or an unlabeled .srt whose language it detects) and the file's own embedded tracks. Ignore image subs if your players can't show them (or have to transcode for them) and you'd rather have a text .srt.
After a download, shift the subtitle timing to match the video's own audio (ffsubsync, offline). Requires the ffsubsync Python package on the server; a failed sync keeps the original file.

Each provider is tried in order, top first, until subtitles are found. Whisper stays pinned last as the last resort when enabled. API keys live under Services → OpenSubtitles, SubDL, SubSource. Embedded needs no key.
Last-resort fallback: when no provider has subtitles, this server transcribes the video's own audio — no API key, no quota, fully offline after the one-time model download. Transcription runs in the background subtitle worker (a 45-minute episode takes roughly 10–20 minutes on a typical CPU). Requires the faster-whisper Python package on the server.
