Retry Logic

What happens when a download is rejected
i
Controls what happens when a downloaded file is rejected (AcoustID mismatch, wrong version, or duration/integrity failure) — independent of post-processing. When on, SoulSync automatically tries the next-best candidate instead of failing the track. Off = quarantine and fail immediately.
i
Give every source (Soulseek, then HiFi/Tidal/…) its own retry budget. Each source spends queries × retries-per-query attempts before the track moves on. Worst case across two sources can mean many downloads — use for hard-to-match tracks (e.g. CJK artist names). Requires the option above.
i
In exhaustive mode, how many candidates to try per search query per source. The per-source budget is number of search queries × this value. Only used when Exhaustive retry is on.
i
When retries are fully exhausted and every candidate for a track failed the same version mismatch (e.g. only an instrumental exists), accept the best (first-tried) one instead of leaving the track missing. Only AcoustID is bypassed — integrity/duration/bit-depth checks still run, so truncated or genuinely wrong files are never let through. Off = leave such tracks failed.
i
How many quarantined candidates must have failed the same version mismatch before the last-resort acceptance kicks in. Higher = more confirmation that no correct version exists. Only used when the option above is on.
i
When a rejected file is followed by a candidate that imports fine, the rejected files leave Review on their own. They go to the Downloads recycle bin, so you can restore one to Review. Automatic quality upgrades never send anything to Review either way: if nothing verifies, the file you already have stays.
i

Album Publishing

When album downloads appear in your library
i
Off by default — with this off, tracks appear in your library as they finish downloading (unchanged behavior). When on, the tracks of an album download are staged privately and only moved into your media library once the whole album completes, so Plex/Jellyfin/Navidrome never shows a half-loaded album while it's still downloading. If a batch stalls or fails, its tracks stay in staging (never your library) and the failed tracks remain retryable in your wishlist. That private staging area is SoulSync's own working folder, storage/album_bundle_staging/<batch id> — it is not the Staging path set under Library, which is a different folder for a different job. It is emptied when the batch finishes. If a crash leaves one behind, the next start moves anything still holding audio into the Downloads recycle bin (labelled “Stalled album download”) rather than deleting it, so a stalled album is recoverable instead of gone. Only affects full-album and wishlist-album downloads — single tracks and album top-ups (completeness fills) are unaffected. Tracks stay on your wishlist until the album is actually published, so an interrupted album is always retryable.
i
On by default, and only relevant when album publishing above is on. If SoulSync restarts or crashes part-way through an album, the tracks it had already finished are left in the private staging folder, where no media server can see them. On the next start SoulSync moves those finished tracks into your library, and the tracks it never got to are still on your wishlist, so the album fills itself in. Turn this off to keep strict quarantine instead: the interrupted album stays hidden until you deal with it by hand. Files are never deleted either way.
