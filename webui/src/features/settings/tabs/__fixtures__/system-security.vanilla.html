Security & Access

PIN · user accounts · reverse proxy
By default, anyone who can reach SoulSync on your network can use it. Protect access below with a simple shared PIN, or full user accounts with passwords — you only need one. The last group is just for exposing SoulSync over the internet.

Set a PIN before you can turn on the lock screen.

🌐 Reverse proxy & remote access

Only needed if you expose SoulSync to the internet behind nginx / Caddy / Traefik. See Support/REVERSE-PROXY.md.
Trusts the proxy's X-Forwarded-* headers, marks the session cookie HTTPS-only, and adds security headers. Leave OFF for direct / LAN access over http:// — it would otherwise break plain-HTTP login. Takes effect after a restart.
If an auth proxy (Authelia / Authentik / oauth2-proxy) logs users in in front of SoulSync, enter the header it sets and SoulSync trusts it. Only set this behind a proxy that strips any client-supplied copy of the header. Blank = off.
Origins (full URL, no trailing slash) allowed to open WebSocket connections — one per line or comma-separated. Empty = same-origin only (the secure default; fine for direct access and most reverse-proxy setups). Add your public domain if live updates fail behind a proxy. * on its own line allows any origin (insecure).
