Subtitles
Fetch external .srt files next to the video from the provider chain below, only for what's missing. On by default for new imports — free tiers are quota-limited (~20 downloads/day each), so anything missed is retried later.
Language codes to fetch, in priority order (e.g. en,es). One .srt per language is written as <video>.<lang>.srt. Each code is 2–3 letters; separate codes with commas, spaces, or semicolons.
A tiebreak only, never a filter: when two subtitles score the same, the hearing-impaired one (sound cues, speaker names) wins.
On top of the full track, fetch a forced (foreign-parts-only) track per language, written as <video>.<lang>.forced.srt — the lines for scenes in another language, for when you watch without full subtitles. Many titles have none, so these often stay missing.
Before fetching, SoulSync checks what the video already has: any sidecar next to it (.en.srt, .eng.srt, .English.sdh.srt, or an unlabeled .srt whose language it detects) and the file's own embedded tracks. Ignore image subs if your players can't show them (or have to transcode for them) and you'd rather have a text .srt.
After a download, shift the subtitle timing to match the video's own audio (ffsubsync, offline). Requires the ffsubsync Python package on the server; a failed sync keeps the original file.

Provider chain
Each provider is tried in order, top first, until subtitles are found. Whisper stays pinned last as the last resort when enabled. API keys live under Services → OpenSubtitles, SubDL, SubSource. Embedded needs no key.
Last-resort fallback: when no provider has subtitles, this server transcribes the video's own audio — no API key, no quota, fully offline after the one-time model download. Transcription runs in the background subtitle worker (a 45-minute episode takes roughly 10–20 minutes on a typical CPU). Requires the faster-whisper Python package on the server.
