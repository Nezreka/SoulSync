Metadata Source

i
Where artist, album, and track metadata comes from:
• Spotify — official Spotify; connect your account in the Spotify section below.
• Spotify (no auth) — the same Spotify catalog with no account needed. It's unofficial and best-effort (may break if Spotify changes its site) and can't read your personal library or playlists.

Tip: if you pick Spotify (no auth) and later connect a real Spotify account, it uses the official account normally and only falls back to no-auth while Spotify is rate-limited — then switches back automatically.

Quality

Profile Format priorities, bitrate, bit depth
Edits below are saved per preset — switch away and back and your changes are still there.
i
How it works: Each download source is checked against this list top-down. The first target a source can satisfy wins; a source that meets no target is skipped for the next one (source priority still decides between sources that can). For lossless, bit depth + sample rate decide the match. For MP3/AAC the bitrate is a minimum threshold (≥), so VBR and mono files aren't falsely rejected. After download the real file is verified against the same list. With fallback off, a track is left missing rather than accepting a quality below every target.

Acquisition vs retained output: Downsample and Lossy Copy run only after the downloaded file passes this gate. SoulSync remembers the acquired quality, so intentionally retaining 16/44.1 or a lossy-only output does not make the same track appear as an upgrade again.
i
No upgrades never replaces a file that already exists.

Any accepted target stops upgrade findings as soon as a file matches any target in the list.

Selected target or better keeps the Quality Upgrade job proposing replacements until the file reaches the selected rank.
i
Source priority goes through your sources in order and downloads from the first one that has the track. Fastest, fewest lookups.

Best quality asks every source, then downloads the highest-quality copy it found — even if a faster source also had a lower-quality one. Slower and more API calls, but you never settle for a worse file when a better one exists.

Either way, the per-source retry limits stay the same.
i
A single source often returns several copies of the same track.

Off (default): the most likely-correct / fastest copy is downloaded first — the original behaviour.

On: the highest-quality copy (per your target list above) is downloaded first instead; correctness and speed only break ties.

Nothing is skipped and the source order doesn't change, so a track can't go missing — it just prefers the better copy. (This is always how Best quality works, which is why this option only appears for Source priority.)
i
This does not mean "walk down my list" — the list already does that on its own.

When on, a file that matches none of your targets (e.g. a 16-bit FLAC or an MP3 when you only listed 24-bit) is accepted anyway as a last resort.

Turn it off to strictly enforce your list — anything off-list is then quarantined instead of completed.

Quality on Import

Profile Apply the profile to manually imported files
i
When importing from Staging, if a track already exists in your library at a lower quality (e.g. MP3), it will be replaced with the higher quality version (e.g. FLAC). If disabled, existing tracks are always kept and the import file is skipped.

Note: imported files are always checked against your Quality Profile's priority list above — there's no separate on/off switch for that, since an empty list (or Fallback turned on) already means "accept anything."

Post-Download Conversion

Profile Downsample hi-res, make lossy copies
i
When a 24-bit or high sample-rate FLAC is downloaded, it is automatically converted to 16-bit/44.1kHz. The hi-res original is replaced, not kept alongside. Its acquired quality is remembered for upgrade decisions, preventing a download/downsample loop. Requires ffmpeg.
i
After downloading a lossless file, a lossy derivative at the selected codec and bitrate is created in the same folder. When the source is kept, it remains the canonical quality and the derivative is treated as a companion version. Requires ffmpeg.
Warning: The acquired lossless file will be permanently deleted after the output is verified. Its acquisition quality remains recorded, so this retention choice is not shown as a new upgrade.
One profile, two decisions: the quality list controls what SoulSync acquires; these options control what it retains. A retained lossless + lossy pair is one track with two file versions, not two duplicate tracks.

When on, a track that AcoustID runs but cannot confirm (no fingerprint match / cross-script metadata — the ⚠ "unverified" case) is quarantined instead of being allowed into the library. Downloads then try the next candidate; imports just quarantine (no candidate to retry). Only a clean AcoustID pass is kept.

⚠️ Use with care. AcoustID "could not confirm" is common for perfectly good tracks — anything not in its fingerprint database: new/obscure releases, classical, remixes, live cuts, remasters, non-Latin-script titles. With this on, all of those get quarantined, so you may end up with many legitimate files to review and approve by hand. Nothing is lost (quarantined files can be approved), but expect manual cleanup. Leave this off to keep the safer default: unconfirmed tracks import with the ⚠ "unverified" badge so you can review them without anything being blocked. Transient lookup errors (rate-limit / outage) always import, so an AcoustID outage never stalls you. Requires AcoustID enabled.

Retry Logic

What happens when a download is rejected
i
Controls what happens when a downloaded file is rejected (AcoustID mismatch, wrong version, or duration/integrity failure) — independent of post-processing. When on, SoulSync automatically tries the next-best candidate instead of failing the track. Off = quarantine and fail immediately.
i
Give every source (Soulseek, then HiFi/Tidal/…) its own retry budget. Each source spends queries × retries-per-query attempts before the track moves on. Worst case across two sources can mean many downloads — use for hard-to-match tracks (e.g. CJK artist names). Requires the option above.
i
In exhaustive mode, how many candidates to try per search query per source. The per-source budget is number of search queries × this value. Only used when Exhaustive retry is on.
i
When retries are fully exhausted and every candidate for a track failed the same version mismatch (e.g. only an instrumental exists), accept the best (first-tried) one instead of leaving the track missing. Only AcoustID is bypassed — integrity/duration/bit-depth checks still run, so truncated or genuinely wrong files are never let through. Off = leave such tracks failed.
i
How many quarantined candidates must have failed the same version mismatch before the last-resort acceptance kicks in. Higher = more confirmation that no correct version exists. Only used when the option above is on.

Album Publishing

When album downloads appear in your library
i
Off by default — with this off, tracks appear in your library as they finish downloading (unchanged behavior). When on, the tracks of an album download are staged privately and only moved into your media library once the whole album completes, so Plex/Jellyfin/Navidrome never shows a half-loaded album while it's still downloading. If a batch stalls or fails, its tracks stay in staging (never your library) and the failed tracks remain retryable in your wishlist. That private staging area is SoulSync's own working folder, storage/album_bundle_staging/<batch id> — it is not the Staging path set under Library, which is a different folder for a different job. It is emptied when the batch finishes. If a crash leaves one behind, the next start moves anything still holding audio into the Downloads recycle bin (labelled “Stalled album download”) rather than deleting it, so a stalled album is recoverable instead of gone. Only affects full-album and wishlist-album downloads — single tracks and album top-ups (completeness fills) are unaffected.
